# Revision4.0: no-image handling and unpaced VGA benchmark

Built offline; not installed. Camera remains3.9.8-bit640x480YUY2; advertised host request ceiling60fps (166666100ns units), not a measured capability. No10-bit format or new USB kernel.

Actual3.9failure record is valid typed metadata with ImageAttach0/handle0. Original Sony RTOS helpers skip all pixel DMM operations; original Linux getter accepts the same bytes. New code recognizes ONLY a stable, structurally validated no-attachment/zero-handle case, closes/frees its known metadata transfer(mode2), then issues existing matched pin SendComp. No pixel credit is invented. Invalid metadata, unknown replies, failed pixel Open, ambiguous DMA still fault/quarantine. Pixel/source lifetime rules remain strict. One session per cold boot.

Removed100ms USB producer pacing,150ms allocation-retry sleep and1ms metadata-retry sleeps. Eight immediate read-pairs remain bounded; removal of settling sleeps can make some transient metadata failures more frequent. Native IPC receives and hardware completion fences remain, returning promptly when events/completions exist. Empty source/host-busy polling calls sched_yield without a timed sleep. Staging readiness timeout now uses3seconds of monotonic elapsed time, not30fast polls. No usleep/sleep/nanosleep import remains in the module.

Timing uses ARM EABI syscall263 CLOCK_MONOTONIC and wrapping32-bit microseconds; durations must be interpreted within71minutes. BENCH_PROGRESS/FINAL contain completed frames, elapsed microseconds and native SEND count. BENCH_LOOKUP contains events, summed lookup microseconds and maximum; BENCH_SDF contains frame count, summed synchronous resize microseconds and maximum. BENCH_NO_IMAGE records no-image count/clock errors. BENCH_USB contains submitted frame count and monotonic microseconds. Counterclock failure invalidates timings; frontend readiness timeout is not based on poll count. Backend hot success traces are sampled/capped and deferred to stop/fault; periodic frontend telemetry still writes flash, so instrumented rates include that overhead. A camera reboot can lose unflushed telemetry. Original source's compression/precision differs from the uncompressed VGA destination; no new raw/10-bit claim.

39real worker C cases cover100frame streams, no-image->image transitions,20no-image events, stop on no-image, metadata Close/Free/SendComp failures, existing malformed and uncertain-reference paths, and forbid timed sleeps. ARM producer tests cover actual submission,1000pending yields, elapsed-time timeout, EBUSY retention, actual descriptor fields and no-sleep imports. Original API/prologue, PIC, ISA and paired installer/rollback checks are included. All hardware/DMA services in offline tests are mocked. Stability and fps require a real camera run.

Guarded installer baseline is exact3.9; default rollback restores3.9pair, --bars restores stable2.4p wrapper plus separate original kernel. Never replace mapped libraries; fresh boot, exact hashes/mappings, healthy storage and owned-log archiving are required. Preserve /tmp/kikilog.dat, original .local/logs/fonts/tools. Reboot-f alone does not prove fresh initialization; use documented native WBI controls only when applicable. First benchmark should be bounded, with OBS closed, then service return for logs. Do not remove hardware fences to chase speed.
