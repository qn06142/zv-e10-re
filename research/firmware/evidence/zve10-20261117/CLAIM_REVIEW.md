# Review of the supplied UVC and Bayer hook mapping

File-based review performed 17 November, centralized 18 November 2026. Inputs were local source, ELF symbols, saved hardware captures and av-cam.bin disassembly for MD5 cdcae9d4fdbf66a33704a4c7564e346d at base 0x635c6000. No new hardware run was performed.

| Claim | Finding | Source |
| --- | --- | --- |
| v25 hooks worker lifecycle and exposes yuy2_live_bind | Supported by the source. The six exact offsets are 0x7aa8, 0x903e, 0x8f9c, 0x8dbe, 0x894c and 0x83c8. | [v25 source](../../yuy2_transport_v25/yuy2_640_v25.c). |
| Either YC or native Bayer plugs into raw_live_ops unchanged | Contradicted by format validation. The source accepts YUY2, NV16 and NV12. v25 initializes a 640×480 destination. Bayer needs its own validated format/transport handling. | [v25 live-source core](../../yuy2_transport_v25/raw_live_source.c). |
| v25 acquires an owned unit at fixed 0x15b00000 | It requests type 0x276 and obtains the physical address and capacity from allocation. A historical address cannot replace that runtime result. | [v25 allocation](../../yuy2_transport_v25/yuy2_640_v25.c). |
| bayer_tap_on_frame_ready submits directly to usbg_video | Contradicted by implementation. It fills a structure and updates counters. There is no ioctl, producer lease, DMA completion wait or coherency operation. It assumes four slots. | [Bayer tap source](../../raw_frame_source/verified_bayer/live_bayer_tap_v01/bayer_tap.c). |
| The Bayer tap submission struct matches the driver | Contradicted by the checked ABI. The tap declares slot_id then length_bytes. The existing eight-byte event is size then physical. | [Bayer header](../../raw_frame_source/verified_bayer/live_bayer_tap_v01/bayer_tap.h), [USB ABI audit](../../../../docs/usb/uvc_raw_frame_source_prompt.md). |
| Existing gadget gives zero-copy Bayer delivery | The audited driver copies the source through DMA330 into USB staging. The claimed zero-copy path is unimplemented. | [USB lifetime audit](../../raw_frame_source/verified_yc/evidence/usb-lifetime-20261029/REPORT.md). |
| 0xf002 proves DMA completion | Contradicted. It checks staging availability. The audited submit timeout path can mark staging ready and return success. | [USB lifetime audit](../../raw_frame_source/verified_yc/evidence/usb-lifetime-20261029/REPORT.md). |
| raw_live_sony.c is a recovered hardware backend | The checked v25 copy defaults subscription state and can synthesize physical extents. It still contains the withdrawn opcode-0x400 model. An actual subscription and wire-level acquisition contract remain unresolved. The recovery document describes a stricter guarded variant than this v25 copy. | [v25 backend](../../yuy2_transport_v25/raw_live_sony.c), [withdrawal and recovery](../../../../docs/usb/uvc_sony_backend_recovery.md). |
| Live-view metadata handles cycle through 0x0059000e and 0x01670464 | Supported as DMM activity. Snapshots contain changed handles of type 0x000e0b00 and the named operation records. | [DMM snapshots](additional-captures/live_view_dmm_extents_units2.txt). |
| Recording adds type 0x2d8 and 0x289 | Supported in the supplied recording snapshots. Type identity does not establish Bayer, packed format or a specific pipeline role. | [Recording snapshot](additional-captures/rec_4k24_full_1.txt). |
| DMM activity is aligned with 48 Hz preview frames | Timing markers and DMM snapshots were observed independently. No shared frame ID or timestamp correlation establishes that exact alignment. | [Timestamped markers](codex/sensor-markers.tsv), [DMM snapshots](additional-captures/live_view_dmm_extents_units2.txt). |
| LiRo IRQ 74/75 activity is near 24 Hz | Supported by saved counter deltas. In live view each rises 25 over 1.05 uptime seconds, about 23.8/s. In recording each rises 32 over 1.31 seconds, about 24.4/s. Reads are sequential, so the rates are approximate. Their sensor DMA completion meaning remains open. | [Live view](additional-captures/live_view_full_1.txt), [recording](additional-captures/rec_4k24_full_1.txt). |
| SetImgRd and camera-core markers occur near 24 Hz | Supported by the rearmed live-view windows. This establishes marker cadence. | [Raw trace](codex/live-view-rearmed.txt), [selected markers](codex/sensor-markers.tsv). |
| No RAW DMM stream exists in these modes | Known RAW unit IDs were absent in sampled tables. This is a sampling result and leaves unexposed/transient allocations and alternative representations open. | [DMM captures](README.md). |
| RawInfo and setRawResolution methods exist | Confirmed in the ELF dynamic symbols. Their names and accessors do not certify an active live Bayer stream or its format. | Local inputs dumps/camera_2025/usr/usr/lib/dataflowInfraFramework.so and libBizFw.so. |
| DFE slots 3, 9, 10, 11 and 14 are registration leads | Confirmed by disassembly of registration paths at 0x6379ed04 and 0x639df964. Function 0x6379cfdc registers callbacks. Slot-10 callback 0x6379ef08 reads facts via 0x6379e900 and signals event 0x16. | Original local disassembly provenance was the supplied analysis session. The checked firmware identity is recorded above. |
| These DFE callbacks identify a safe live Bayer copy window | Unresolved. Slot-to-hardware fact semantics, actual destination metadata, completion, producer reuse and cache visibility need runtime evidence. The earlier native event bridge resolves to RcResize. | [Native dump correction](../../raw_frame_source/verified_bayer/evidence/native-dump-20261031/REPORT.md). |
| Native still RAW dump is an available finished capture path | Offline writer/receiver dispatch and opened-buffer forwarding are recovered. One-shot activation, actual saved Bayer content and lifetime remain unverified on hardware. The later audit corrects the global gate to selector==9. | [Receiver audit](../../raw_frame_source/verified_bayer/evidence/native-dump-20261031/REPORT.md), [later gate audit](../../raw_frame_source/verified_bayer/evidence/raw-pipeline-audit-20261031/REPORT.md). |

The concrete open boundary is one live-view DFE operation associated with a completed pre-demosaic buffer and a known lifetime. A proposed custom UIPC notification carries metadata only. It cannot extend the producer's ownership interval by itself.
